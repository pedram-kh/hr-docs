# ADR-0022 — The reference-fact segmentation agent (one-fact-per-scope; source-validity + duplicate-flag; resolution is 7d)

**Status:** accepted (Sprint 7b-2)

## Context

ADR-0021 (Sprint 7b-1) built the **Structured Reference Knowledge** substrate — the `reference_facts` class with structurally-bounded authority, `document_type` routing, the inert-until-verified spine, and a **manual** create/verify path — and **reserved** the `ai_agent` source lane unwritten. Sprint **7b-2** lights that lane: an AI agent that reads a multi-scope `reference_source` (`.docx`/`.xlsx`) and **proposes** per-scope facts into `reference_facts`.

This is the **risky proposer**. The real fixtures (two *periodo de prueba* `.docx`, one salary `.xlsx`) are organized as **TERRITORY → SECTOR → group → value** blocks where scope is *carried* down by headers, and the same sector+group takes a **different value by province** (COEAS Álava G1 = *5 meses*; COEAS Estatal/Andalucía G1 = *6 meses*). The dominant failure mode is therefore not a missed fact — it is a **confident, exact, mis-scoped** fact (Álava's 5 silently attributed to Andalucía). A second real hazard: the `/read-structured` section split is **style-dependent and unreliable** across the two files (file 1 territory headers are `Título 1`; file 2's are plain `Normal` paragraphs), so the reader's boundaries cannot be trusted as scope.

This sits beside **ADR-0007** (hr-ai reads/returns, never migrates; hr-backend owns writes + schema), **ADR-0011** (vocabulary is bind-only, never minted), **ADR-0020** (AI proposals inert until a human verifies), and **ADR-0021** (the substrate + authority floor). The danger to foreclose, by construction: a **generated fact that is wrong but rubber-stampable** (confident, plausible, unflagged), and a **salary figure dressed as a reference fact**.

## Decision

Reuse 7a's proven **propose-pattern** verbatim — a queued job → an hr-ai cognitive endpoint that reads-and-returns → a single hr-backend persist service that writes append-only `ai_agent` provenance — and write into 7b-1's `reference_facts`. The **only** new cognition is *segment a multi-scope source into per-scope facts and bind each scope to a real `convenio_id`*. Seven load-bearing rules, enforced server-side and re-proven (not rebuilt) by test (`Sprint7b2SegmentationInvariantTest`):

1. **The header-carry segmentation contract (the load-bearing instruction).** Each value line's scope is the **most-recently-seen TERRITORY + SECTOR**; SECTOR resets on each new sector header, **both** reset on each new territory header. The agent **re-derives** this hierarchy from the **text content**, not from the reader's `pages[]`/`label` boundaries (which are unreliable — §Context). A single inherited-province error is the worst outcome, so this is the highest-leverage prompt detail.

2. **Bind, never mint (ADR-0011), validated against a closed convenio-centric vocabulary.** hr-backend passes a **convenio-centric** candidate list (each convenio carries its derived territory + sector + job categories + aliases) because *scope rides the convenio*. The model returns `convenio_id` (+ optional nested `job_category_id`, + approved `topic_id`); hr-ai **closed-set-validates every id** before returning — a hallucinated id can never reach hr-backend. If no convenio matches (a statutory-fallback block), the agent **flags uncertain or omits** — it **never force-binds** a wrong convenio (the ADR-0021 carried limitation: scope rides the convenio).

3. **One fact per scope (the multi-value rule).** A `Grupo X` block — even when its contract-type values span several lines (file 1's Hostelería: *90/75/60* across four lines) — is **one** fact; the breakdown lives in `value` + `raw_values`. A group *range* ("Grupos 1 y 2", "Grupos 3,4,5 y 6") is one fact for that range. The **answerable unit is the scope.**

4. **The null-`job_category` collision fix — `group_label` joins the logical key.** Group categories are salary-derived and mostly unseeded, so `job_category_id` is usually null; the 7b-1 key `(convenio_id, topic_id, job_category_id, validity_start, validity_end)` would then **collide** for every group of the same convenio. The additive **`group_label varchar NULL`** column carries the group identity and is folded into the key → `(convenio_id, topic_id, job_category_id, group_label, validity_start, validity_end)`. This is what lets all of a convenio's per-group facts coexist, and what makes the upsert idempotent.

5. **Propose-with-source-validity; flag obvious duplicates; never resolve (7d).** Each fact is tagged with **its source document's** validity (hr-backend derives `validity_start/end` from the `documents` row a human set at ingest — the **agent does not parse dates from prose**). An **obvious duplicate** = a logical-key collision (same convenio+topic+group+validity, normalized) with a **differing value** (e.g. Navarra Intervención Social G2 = *6 meses* in file 1 → *4 meses* in file 2). It is flagged via **`duplicate_of_id` + `uncertainty.field='version'`** and a `tag_events` note — **a signal surfaced to the human, never a resolution.** Semantic comparison / version-wins is **7d**; we do not build conflict detection twice.

6. **Err low on authority, flag on uncertainty; the agent never verifies (the inherited invariants, re-proven).** `authority_level` is **forced** to `structured_reference` (INVARIANT 1 — the column cannot store higher); `source='ai_agent'`, `status='needs_review'` are hardcoded; the only writer of `verified` is the human `ReferenceFactController::verify()`. There is **no code path** from the segmentation service to `salary_table_rows` (INVARIANT 2 — routing rides the `reference_source` tag; the xlsx yields reference facts or nothing, **never** a salary row). Where scope is unclear the agent **flags uncertain rather than guesses** — a flagged-uncertain fact is a success (the human decides); a confidently mis-scoped fact is the failure.

7. **The safety is the UX.** Every fact carries a mandatory **`source_excerpt`** (the exact line + its `ÁLAVA › COEAS ÁLAVA › Grupo 1: …` header trail), a **`confidence`** decimal, and a structured **`uncertainty` jsonb** `{field, reason}`. The review queue sorts **uncertain-first** (uncertainty set, then ascending confidence). The reviewer confirms *"did the source really say Álava?"* against the quote, not by re-reading the file. **Fuchsia** (`--provenance-ai`, reserved-and-unlit since ADR-0020/0021) is **now lit** for `is_ai_proposed` facts; on verify it reverts, the AI origin persisting only as the `ai_agent` provenance dot. A **`rejected`** status (additive enum value) makes an excluded proposal auditable without deletion.

## Consequences

- **The eval is the deliverable, not the code.** The primary output is the measured accuracy report in `sprint-07b-2/review.md` (per-fixture table + the mis-scoped enumeration + the *catchable-vs-drowning* judgement), scored against a hand-built gold set (`sprint-07b-2/eval/gold-set.json`) by a reproducible, LLM-decoupled scorer (`score_eval.py`). **Iterating the prompt against this eval is expected**, for this one sprint.
- **Additive migrations only (ADR-0007).** One migration adds `group_label`, `confidence`, `uncertainty`, `source_excerpt`, `proposal_batch_id`, `duplicate_of_id` to `reference_facts` and extends the `status` enum with `rejected`; one idempotent data migration (in lockstep with `TopicSeeder`) seeds the approved **`periodo de prueba`** topic the agent binds to. **No hr-ai migration** (`/segment-facts` reads-and-returns).
- **No answering-from-facts (7c); 2b frozen.** Nothing teaches the answer loop to query `reference_facts`. A proposed-and-verified fact being not-yet-answerable is correct.
- **No semantic-conflict resolution (7d).** Duplicate detection is exact-key + different-value → flag only; no winner is ever picked, nothing is deleted or merged.
- **Carried limitation (unchanged from ADR-0021):** scope rides the convenio, so statutory-fallback blocks (file 2's *"ámbito estatal cuando no hay convenio"* / *"Estatuto de los Trabajadores"*) have no convenio to bind and are flagged-uncertain or skipped — never force-bound. The gold set encodes these as `expected_skips`.
- The inherited safety net (ADR-0020/0021) is **re-proven, not rebuilt**: the six invariant tests assert the lane is inert, the authority floor holds, segmentation writes zero salary rows, re-runs are idempotent on the extended key, the agent never verifies, and a same-scope/different-value collision flags without merging. Cites ADR-0007, ADR-0011, ADR-0020, ADR-0021.
