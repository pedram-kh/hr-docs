# ADR-0021 — Structured Reference Knowledge: a non-vectorized scoped-fact class with structurally-bounded authority

**Status:** accepted (Sprint 7b-1)

## Context

The platform has two knowledge classes today: **prose** (PDF convenios chunked + embedded, retrieved by similarity — ADR-0006) and **salary** (`salary_tables`/`salary_table_rows`, relational, queried-not-embedded, scoped via the convenio — ADR-0006). The remaining corpus is a **structured-reference tail**: non-salary rules that live in `.docx`/`.xlsx` and read as short, scoped facts — *"periodo de prueba: 90/75 días"*, working-day calendars, SMI references, complement rules. These are not prose to paraphrase and not a salary grid to total; they are **discrete facts, each scoped to a convenio**, that must be cited verbatim.

Two real gaps block them: (1) **format** — `/extract` is PDF-only (ADR-0010) and `.xlsx` is read *only* on the salary path (`/extract-salary`), so `.docx` is unreadable and a non-salary `.xlsx` has no home; (2) **shape** — there is no store for a scoped, source-linked, verbatim fact. Sprint **7b** introduces the class. It is split: **7b-1 (this)** builds the substrate + the **manual** create/verify path; **7b-2** adds the AI segmentation agent (the risky proposer); **7c** teaches the answer engine to query verified facts. 7b-1 must make the class *real, storable, reviewable, and visible* on a proven foundation **before** the AI is layered on — and must not touch the frozen answer loop (2b).

This sits on the safety axis beside **ADR-0006** (structured = queried-not-embedded), **ADR-0007** (hr-backend owns all writes; hr-ai never migrates), **ADR-0011** (vocabulary grows only by deliberate human action), and **ADR-0020** (AI proposals are inert until a human verifies). The danger to foreclose, by construction: **a generated fact outranking the law**, and **a salary source being silently swallowed** (or vice-versa).

## Decision

A new structured class, **`reference_facts`**, generalizing the salary pattern (data-model §6) with the same discipline. Five load-bearing rules, enforced server-side and proven by test (`Sprint7b1ReferenceFactInvariantTest`):

1. **Authority is structurally bounded — a fact can NEVER outrank a convenio (INVARIANT 1).** Enforced **two** ways: (a) the `authority_level` column is an enum/CHECK that holds **only** `structured_reference` — it *cannot physically store* `official_convenio`/`national_law`; (b) `Store`/`UpdateReferenceFactRequest` accept `authority_level in: structured_reference` only and **reject (422)** anything higher — the Sprint-6 reject-not-clamp discipline (ADR-0019). "Nothing the system generates outranks the law," by construction. Lower/equal levels may be *added* later; the two top levels are never addable.

2. **Routing rides `document_type`, never content (INVARIANT 2).** A new closed-vocabulary code **`reference_source`** is the deliberate routing tag. A `salary_tables`-tagged `.xlsx` reaches `salary_table_rows` *only* via `salary:import`; a `reference_source`-tagged `.docx`/`.xlsx` reaches `reference_facts` *only* via the manual path. The reference writer **never** writes a `salary_table_rows` row (even if the source contains SMI figures — they land as a fact's `value`/`raw_values`); `salary:import` filters `document_type = salary_tables` and so never picks up a reference source. One file, one tag, one writer — no content-sniffing.

3. **Inert until verified — the ADR-0020 spine, reused.** A fact lands `status = needs_review` and is **not answerable** until a human verifies it (`verified_by`/`verified_at`). Since 7c is unbuilt, **no fact is answerable yet — correct for this slice.** Provenance is **append-only** in `tag_events` (`entity_type = 'reference_fact'`): created → verified → edited, never a rewrite. The `source` lane reserves **`ai_agent`** (unwritten in 7b-1 — the manual path is the only writer; it lights in 7b-2).

4. **hr-ai reads, hr-backend persists (ADR-0007 preserved) — the format extension to ADR-0010.** A single endpoint `POST /read-structured` (internal-token guarded) reads a non-salary `.docx` (via **python-docx**) or `.xlsx` (via the salary path's **openpyxl**) and **returns** per-section/per-sheet content. It writes nothing, holds no DB access, never migrates. It is a **content-extraction utility only** — it does **not** decide scope or segment into facts (that is 7b-2). hr-backend stores the returned content as **display `document_pages`** (one row per docx section / xlsx sheet) and **never** `document_chunks` — these are queried-not-embedded (ADR-0006).

5. **Scope generalizes the salary pattern; vocabulary is bind-only (ADR-0011).** A fact is scoped via `convenio_id` (the FK that fixes **derived** territory + sector — never stored independently); finer scope via nullable `job_category_id` (must belong to the convenio) and `topic_id` (an **approved** topic only). The fact is `value` (text) + `raw_values` (jsonb, verbatim — the salary discipline), with `validity_start/end`, `source_document_id` + a free-form `source_locator`. No new vocabulary is ever minted from fact entry. The **logical key** the 7b-2 AI will upsert on is `(convenio_id, topic_id, job_category_id, validity_start, validity_end)` — recorded now, **no hard unique constraint** in 7b-1 (a manual create is a single deliberate human action).

The manual UI reuses the Sprint-3 Knowledge Center: a **distinct-badged leaf** (`knowledge_type = reference_fact`) under its convenio-derived scope (territory/sector/topic), a **fact card** (value, raw, source link + locator, topic, validity, the visible authority lock, the provenance timeline), the **verify** action (the Sprint-3 confirm), and the **scope-edit 409 confirm gate**. Writes are gated by `knowledge.edit` (Q6 — the human is author *and* verifier in 7b-1; when 7b-2 adds the AI proposer, the verify bar gets the harder look).

## Consequences

- The answer to *"can a generated fact outrank the convenio?"* is **no, by construction** — the column can't store a higher level and the request rejects it (422). This is the AEPD / comité answer beside ADR-0018/0019/0020.
- **No fuchsia this slice.** The `--provenance-ai` token stays reserved for **unverified AI** (ADR-0020); 7b-1 has no AI writer, so the `is_ai_proposed` flag is always false and a manual unverified fact uses the neutral *needs-review* treatment, exactly like a document under review.
- The answer loop is **not** touched (2b frozen): `/read-structured` is a separate upstream read; nothing teaches `/retrieve` `/synthesise` to query `reference_facts`. **A verified fact being not-yet-answerable is correct** — answering-from-facts is 7c (and it touches the frozen loop, so it is its own deliberate step).
- Additive migrations only: `create_reference_facts_table` + the `reference_source` document_type seed (DocumentTypeSeeder + an idempotent data migration in lockstep). **No** new provenance table (reuse `tag_events`), **no** new permission (reuse `knowledge.edit`), **no** hr-ai migration (it gains an endpoint).
- **Carried gap (not fixed here):** the existing document **confirm** route sits in the open-admin block (UI-hidden via `canEdit`, not server-gated). The new fact **verify** route *is* server-gated (`knowledge.edit`) as planned; tightening the document confirm route to match is logged in `review.md` + the roadmap/deploy notes (a real server-gating gap, same family as the Sprint-5 access findings) and left for a follow-up.
- Accepted limitation (Q10): scope rides the convenio, so a territory-only / no-convenio fact can't be placed — the same limitation documents already have; the canonical fixtures are all convenio-scoped.
