# ADR-0030 — Measurement: read-only, reproducible, embedding-clustered with a real-question label, human-sampled; the coverage map and ledger share one query; τ calibrated against a real 20-pair set (classes overlap; kept at 0.80)

**Status:** accepted (Sprint 8)

## Context

Every other sprint changed what the system *does* — routes, retrieves, synthesises, escalates, publishes. Sprint 8 changes what the system *shows about itself*: deflection, coverage gaps, question clusters, a monthly human quality sample, and (optional) a thumbs signal. None of the data this sprint reads is new — `message_traces.trace` (`router_decision`/`floor_decision`), `escalation_cards` (+ ADR-0029's `explanation_facts`), `employees` (scope + `convenio_group_id`), and `corpus-coverage.md`'s hand-run ledger queries already existed as *facts about the system*; they had never been assembled into a screen, and the one artifact that did exist as code-adjacent (`corpus-coverage.md`) was produced by an LLM agent running ad-hoc SQL by hand, with no service behind it at all.

That gap between "the data already exists" and "nobody can see it without a psql session" is the whole problem this sprint solves, and it comes with a specific hazard: a measurement layer is exactly the kind of feature where it is easy, almost by accident, to (a) let the measurement change what's measured (a query that reads `message_traces` for every dashboard load becomes a de-facto second decision path if anyone ever wires it back in), (b) show a number nobody can reproduce (a hand-typed ledger vs. a computed screen silently drifting), or (c) let an LLM quietly stand in for a definition (labelling a cluster of real user questions with a generated summary, which is exactly the kind of invented-plausible-text failure ADR-0029 named and refused on the HR-explanation side).

## Decision

Five load-bearing rules, stated once here so every screen and command this sprint ships can be checked against the same list rather than five separate ad-hoc judgment calls.

### 1. Read-only over the answer path — no exceptions, proven the same way ADR-0007/0029 already prove it

Every query this sprint adds reads `message_traces`, `escalation_cards`, `employees`, `chat_messages`, `document_chunks`/`reference_facts`/`salary_tables`, or a new sprint-8 table (`analytics_daily_rollups`, `coverage_snapshots`, `question_clusters`, `quality_samples`, `message_feedback`) — never writes back into anything the router, the floor decision, retrieval, synthesis, or grounding read. `Sprint7cAdditivityRegressionTest` (the golden-trace regression) stays green, byte-for-byte, through every one of this sprint's ten build steps — not audited once at the end, but re-run after each step, the same discipline ADR-0029 established for its own escalation-explanation work. `message_feedback` (§4 below) is the sharpest test of this rule: a click stores a row and nothing — not the router, not the floor decision, not any future turn for the same employee — ever reads that row back into a live decision. Aggregates are free; nothing here is a second decision path.

### 2. Every number is reproducible from a named command, and the screen and the export are the SAME query

`stats:deflection`/`stats:rollup`, `stats:escalations-by-fix`, `questions:cluster`, `quality:sample`, and `corpus:coverage` are the source of truth; `AnalyticsController`/`CoverageController`/`QualitySampleController` are thin JSON wrappers over the exact same service classes (`DeflectionAnalytics`, `EscalationFixAnalytics`, `QuestionClusteringService`, `QualitySamplingService`, `CorpusCoverageService`) those commands call — never a second, independently-drifting copy of a definition. `CorpusCoverageService::grid()` is the sharpest instance of this rule: it is the **one** query behind both the Cobertura screen and `corpus:coverage`'s markdown export, proven by an agreement test (two calls against the same DB state return byte-identical data) and a byte-stable export test (the same export run twice produces an empty diff — stable row ordering, no timestamp drift except the header date). `corpus-coverage.md` stops being a hand-run ledger from this sprint forward; it is what `corpus:coverage --print > corpus-coverage.md` produces, nothing else.

### 3. No LLM labels, no LLM summarises, over this sprint's own measurements — the real thing IS the label

Question clustering uses greedy single-link clustering over BGE-M3 embeddings (unit-normalized, so cosine similarity is the dot product) at a threshold τ=0.80, and the cluster's label is its **medoid** — the real member question with the highest mean similarity to every other member, never an LLM-generated summary. This is the direct extension of ADR-0029's refusal to let a model invent the reason an escalation happened: here, the model isn't even asked to paraphrase (as ADR-0029's Layer 2 is) — clustering doesn't call a provider at all, only hr-ai's existing embedding loader via the one new endpoint this sprint adds, `POST /embed-batch` (read-only, internal-token-guarded, batches of ≤256 strings, no DB access, no migration — the same "hr-ai gains no new decision-making surface" posture `/embed-batch`'s sibling calls already hold).

**τ=0.80 shipped unmeasured in the first build; it is now calibrated against a real 20-pair set, and the number is stated rather than hidden — including the fact that it doesn't fully resolve the question.** On staging, 2026-09-10, over a real deploy of this sprint: 20 hand-authored Spanish question pairs — 10 true paraphrases (same intent, different wording) and 10 hard non-pairs (same topic, different intent, e.g. "¿cuántos días de vacaciones tengo?" vs "¿puedo vender mis vacaciones no disfrutadas?") across 5 topics (vacaciones, salario, periodo_de_prueba, permisos, jornada) — were embedded through the real `/embed-batch` endpoint (BGE-M3, not a scripted test double). Full table: `hr-docs/sprints/sprint-08/eval/question-pairs.json` + `review.md`.

| | min | max | mean | n |
|---|---|---|---|---|
| true paraphrases | 0.6846 | 0.9451 | 0.8475 | 10 |
| hard non-pairs | 0.6061 | 0.7772 | 0.6960 | 10 |

**The classes overlap**: the lowest true-paraphrase score (0.6846, "¿tengo permiso retribuido por matrimonio?" vs "¿me dan días pagados si me caso?") is *below* the highest hard-non-pair score (0.7772, "¿cuánto dura mi periodo de prueba?" vs "¿qué pasa si me despiden durante el periodo de prueba?") — no single cosine threshold cleanly separates every true paraphrase from every hard non-pair on this set. Per the sprint's own calibration mandate — *if the classes overlap, keep τ=0.80, say so, and show the overlap* — **τ stays 0.80**, now as a named config value (`config('hr.question_cluster_threshold')`, `HR_QUESTION_CLUSTER_THRESHOLD` env override) rather than a bare class-constant literal, so a future retune is a deploy, not a code change.

**τ=0.80 is not an arbitrary point inside the overlap — it sits entirely above the overlap band** `[0.6846, 0.7772]` on this set: all 10 hard non-pairs score below it (0 false merges), and 9 of the 10 true paraphrases score above it (1 false split — the "permiso por matrimonio" pair). This is the safer failure mode for a never-LLM-labelled, medoid-only cluster: 0.80 trades a few missed true merges for zero wrong merges, rather than the reverse. A second, independent real measurement (this build's Step 5, a different pair — "¿cuántos días de vacaciones tengo?" vs "vacaciones que me corresponden" — scored 0.7916, also below τ) shows the same shape of result on an unrelated pair, not a one-off artifact of this specific 20-pair set.

Every cluster row still logs and displays its own internal min/max pairwise similarity, so a bad merge or a bad split remains eyeball-able directly from the row, without a query. **This should be revisited again once real traffic gives a larger, naturally-occurring pair set** rather than a hand-authored 20-pair one — recorded here as the next step, not closed permanently by this one calibration session.

### 4. Human sampling is the accuracy check, and it protects its own inputs from the very rebuild that produces them

`quality:sample --month --n --seed` draws a stratified (path × territory), seeded, reproducible sample of answered turns each month. Reproducible means exactly that: the same `(month, seed)` pair — `seed` defaults to `crc32($month)`, deterministic and un-gamed — always produces the identical `message_id` set, proven by a dedicated test (`mt_srand` + a fixed sorted-stratum/sorted-member Fisher-Yates consumption order, so incidental DB row ordering can never change the draw). Unlike every OTHER rebuildable Sprint-8 artifact (rollups, clusters, coverage snapshots — all full delete-then-insert replaces), a re-run of `quality:sample` for a month **preserves already-reviewed rows**, replacing only unreviewed (`verdict IS NULL`) ones — a monthly re-draw must never destroy a human reviewer's completed work. A `wrong` verdict opens a fix task through the **existing** ADR-0029 machinery (`EscalationExplainer::explain('quality_sample_wrong', $trace)`, reason=`quality_sample_wrong`) — no parallel task-creation path, no second way for HR-facing "you need to fix something" text to be generated. Opening a sampled turn's conversation is a genuinely new access path and calls `ConversationAccessLogger::logView()` with a `quality_sample:<uuid>` context marker — ADR-0018's "every conversation view is logged" rule extended to cover it explicitly, not left to be an unlogged gap.

### 5. The one new access-control primitive: `analytics.view`, minimally scoped

Today's `EnsureCan`/`RoleSeeder` only had single-ability gates. The spec's access matrix needed `knowledge_editor` to see Cobertura (a knowledge-gap view, squarely inside their existing remit) without gaining Analítica or quality-sample review — an OR-of-two-abilities case `EnsureCan` doesn't support. **Decision: add exactly one new ability, `analytics.view`** (granted to `super_admin`/`hr_agent`/`auditor`), and gate Cobertura specifically on `analytics.view` **OR** `knowledge.edit` via a new, single-purpose `EnsureCanViewCoverage` middleware (`coverage.view` alias) — deliberately a small dedicated check rather than teaching `EnsureCan` to parse compound ability expressions for the one call site that needs it. Quality-sample review reuses `escalation.work` — no new ability invented there; sampling review is escalation-adjacent human work, not a new capability. Proven the same way Sprint 5 proved its own access matrix: a direct-API-hit test per role per screen (`Sprint8AnalyticsAccessTest`), not a UI-only check.

## Consequences

- **Nine additive migrations, zero destructive ones**: `analytics_daily_rollups`, `coverage_snapshots`, `question_clusters` + `question_cluster_members`, `quality_samples`, the `quality_sample_wrong` escalation-reason CHECK-constraint extension (the introspect-drop-readd idiom, reused a fifth time), the `analytics.view` permission seed, `message_feedback`. hr-ai gains exactly one endpoint (`/embed-batch`, read-only, no migration, no new model — BGE-M3 was already loaded for `/retrieve`).
- **A scheduler now exists** (Laravel `withSchedule()` + a `scheduler` compose service running `schedule:run` every minute, mirroring the worker container) where none did before — the nightly rollup/snapshot/cluster/sample jobs need one, and building it was step 1 of this sprint's own order rather than an assumption the plan got to skip.
- **Two new UI primitives, tokens-only** (`.kpi-tile`, the hand-rolled SVG `.chart-bars`/`.chart-line` pair) — matching the plan's own prediction of "at most two genuinely new primitives." Both follow `Hierarchy.tsx`'s `GraphForm` precedent (arithmetic absolute positioning + one SVG overlay, no charting library, no Tailwind).
- **The coverage lens becomes a fifth `Lens` value** (`'coverage'`), reusing the existing `HierarchyNode`/`gap_kind` shape rather than inventing a parallel node type — a gap cell is a leaf whose `gap_kind` is one of `CorpusCoverageService`'s reason codes.
- **`usePaginatedQuery(fetcher)` is extracted** before three more copies of the pre-existing 4×-copy-pasted pagination block were added for the new tabs — a refactor-while-touching, not a new behaviour (the existing pagination tests stay green).
- **Feedback is genuinely optional and shipped last**, proven by construction rather than by promise: `message_feedback` has no foreign key anything else reads, `ChatService`/the router/the floor decision were not touched to add it, and removing the feature would be deleting one migration, one controller method, one route, and one chat-UI component — no unwind required anywhere else.
- **The Estatuto (doc 73) re-chunk decision is measured, not guessed**: this sprint's own evidence query (`authority_used` = `["national_law"]` only, on turns where the asker's convenio has active, on-topic prose) is the concrete trigger condition `roadmap.md`'s Sprint-2c entry deferred to "Sprint 8 follow-up." At the traffic level this environment has (near-zero, per `plan.md` §1.2 — confirmed zero `message_traces` rows in this build's own DB), the query returns zero qualifying turns by construction, and the decision is recorded as **"no evidence, not done"** rather than silently skipped — per the spec's own instruction that a zero result is itself a recorded outcome, not a non-event. See `sprints/sprint-08/review.md` §9 for the query, the exact zero, and the explicit flag that this must be re-run against real staging traffic once it exists.
- **This sprint's own measurements are subject to the same "recorded as evidence, not read into" rule real staging counts needed everywhere else in this project**: the numbers this ADR and `review.md` cite from THIS build were run against a near-empty local/dev database (2 employees, 0 `message_traces` rows) — not real staging traffic. The build could not reach staging over SSH from this environment; every place a real count was needed (§0 of `review.md`, the Estatuto evidence, the eyes-on checklist) is flagged as a blocker requiring a follow-up staging session, not silently filled with placeholder numbers presented as real ones.
- Cites **ADR-0007** (hr-backend owns writes; hr-ai stays a stateless, narrowly-scoped compute service — `/embed-batch` follows the same shape as `/retrieve`'s embedder and `/synthesise`), **ADR-0011/0020** (AI proposes, human verifies — quality sampling's "wrong → task" path is the same spine applied to a sampled turn instead of a proposed tag), **ADR-0017** (the article-boundary splitter this ADR's Estatuto follow-up would reuse verbatim if triggered), **ADR-0018** (every conversation view logged — quality sampling extends the two existing call sites to a third), **ADR-0028** (the group-scope headcount column `CorpusCoverageService`/`QuestionClusteringService` both reuse for their respective headcount weightings), **ADR-0029** (the reason→sub_outcome→fix taxonomy `quality_sample_wrong` extends, and the "nothing AI-generated is ever the thing a fix acts on" rule this ADR's clustering section restates for a different surface).
