# ADR-0039 — A declined turn is possible for exactly one reason, `off_domain`; the rule is a single pure gate whose grant is the only way to build the outcome, re-checked where the turn is written

**Status:** accepted (Slice 13e — plan accepted 2026-10-01, decisions Q1–Q9 on `sprints/sprint-13e/plan.md`). Amends ADR-0029 (the "every escalate shows one fixed message" override now has one named exception, the decline) and ADR-0019 (off-domain guard). Gate passed at CP-1 on 2026-10-01 (`sprints/sprint-13e/review.md`): off-domain 48/48 declined with 0 cards, never-decline sets 0 declines in 82 turns, three live HTTP declines, BL-03 escalating; ≈ $6.84 of the $8 cap.

## Context

Until now a question with nothing to do with work ("capital de Australia") was *escalated*: a card for HR, `EMPLOYEE_ESCALATION_MESSAGE` for the employee. HR's queue filled with questions nobody needed to read, and the deflection rate was dragged down by turns that were never HR's business. The opposite risk is far worse: declining a real work question ("¿me corresponde una excedencia?") tells an employee, with no human in the loop, that their question is not HR's. A decline must therefore be **impossible for any reason other than `off_domain`**, and that has to hold as a rule the code enforces, not a convention reviewers remember.

## Decision

1. **One pure gate.** `App\Services\Decline\DeclineGate::decide(DeclineFacts): DeclineDecision` evaluates every check (never short-circuits) and records each as `{id, pass, detail}`, in order, under `GATE_VERSION = 'dg-1'`:
   D0 kill switch (`hr.decline.enabled`) · D1 reason is exactly `off_domain` and the source is the planner or the admin guard · D2 no baseline-guard hit and no admin `blocked_topic` match (all matches, not the first) · D3 not an explicit request for a human · D4 no accepted normalization topic/canonical · D5 no corpus material · D6 the previous assistant turn was not an `ask`/`needs_category` · D7 no workplace-vocabulary veto (planner source only) · D8 independent router confirmation, label `off_domain` at ≥ `hr.decline.router_confirm_floor` (0.90; planner source only) · D9 for the guard source, the matched rule is `admin_off_domain`.
2. **Four enforcement layers.**
   - **L1 — type.** `TurnOutcome` throws for `decline` without a `DeclineGrant`, for a grant on a non-decline, and for an unknown outcome. `DeclineGrant::fromDecision()` requires a *granted, `off_domain`* decision. The only builder is `TurnOutcome::decline(DeclineGrant, …)`.
   - **L2 — persistence.** `TurnPersister` (the single writer) re-validates the trace as written and, on any violation, **demotes to a `low_confidence` escalate** (the safe direction), writes `trace.decline_demoted` and logs `decline_demoted`.
   - **L3 — structure.** Source-scan tests: nothing outside the factory builds a decline outcome; `Verdict::forceDecline` is the only agent route.
   - **L4 — truth table.** Tests over every reason × every boolean combination of the checks: a decline is granted in exactly one row family.
3. **Option B for the planner floor.** The planner prompt is unchanged (`prompt_version sha256:9f0d13fb…`); a planner `off_domain` becomes a decline only if the router *independently* says `off_domain` at ≥ 0.90 and the D7 veto does not fire. (Option A — a `confidence` field on the planner's `escalate` — is the documented fallback if the staged gate shows B is too strict.) The router call is spent only when D8 is the only failing check.
4. **D7 veto.** A whole-word, accent-insensitive vocabulary of workplace terms (`DeclineVeto::WORDS`, which includes categoría, grupo, excedencia, formación, mutua, paro, jubilación, teletrabajo, …) plus `TopicLexicon::matchTopicKeys`. Planner source only: an admin's own `blocked_topic` pattern is HR's explicit statement and is not second-guessed (golden 04).
5. **Two sources, one outcome.** Agent engine: new boundary `pre_call:escalate`, rule `OffDomainDeclineRule`, `Verdict::forceDecline`, termination reason `declined`. Both engines: the admin `off_domain` row in `PreModelGuards`. The classic engine's *router* `off_domain` stays an escalate (Q2). A denial changes nothing: today's `planner_escalated` / `off_domain` escalate runs untouched, plus a `trace.decline` block (`granted:false`, `denied_by`).
6. **Trace, not column.** `floor_decision.outcome = 'decline'`, `decline_reason = 'off_domain'`, no `escalation_reason`; `trace.decline = {granted, source, reason, checks, denied_by, confirm, gate_version, …}`. No migration (outcome lives in the JSONB trace; the rollup column is `string(32)`).
7. **Copy.** The admin's `off_domain` message if set, else `ChatService::DECLINE_MESSAGE` ("…solo puedo ayudarte con dudas sobre tu trabajo y tu convenio…"). The "if you think this is a work question, ask HR to review it" hint is frontend-only, with a button that goes through the existing review path (`requestReview` now accepts `decline`; sub-outcome `declined_reviewed`).
8. **Measurement.** `declined` is its own figure, excluded from the deflection denominator (answered / (answered + escalated)); declines per day (live == rollup); a "declined this week" ranking computed at read time by exact-text grouping (not the nightly clusters). Historial gets a `declined` bucket and `declined_only` flag.

## Consequences

- Deflection rate has a discontinuity at deploy (declines used to count as escalations); the Analítica period note says so.
- A false decline costs the employee one tap (review button → card for HR); a false escalate costs HR a card. The floor is asymmetric on purpose: every ambiguity resolves to *escalate*.
- `HR_DECLINE_ENABLED` is **off by default** in `config/hr.php` (a fresh environment behaves exactly as before Slice 13e) and on in the staging compose; `phpunit.xml` turns it on for the suite. Off restores the previous behaviour byte-for-byte (golden `04_admin_blocked_topic_flag_off.json`).
- CP-1 decisions: a personal-tax question («renta») stays declined; no change to the veto list. A greeting («Buenas tardes») got a clarifying `ask`, not a decline; a deterministic greeting reply is a separate ticket (roadmap §7).
- Disclosed deviations from the plan: golden 04 re-recorded; `Sprint6GuardrailInvariantTest` split into flag-off/flag-on; the declined ranking uses exact-text grouping; no `statusLabels.outcome` record (`traceOutcomeLabel` is the exhaustiveness guard); an explicit-request question matching an admin `off_domain` row falls through to today's escalate with D3 denied.
