## The two safety invariants (non-negotiable — build + TEST)

1. **A reference fact can NEVER outrank a convenio — enforced two ways (INVARIANT 1).** (a) The `authority_level` enum/CHECK holds **only** `structured_reference` — the column **cannot physically store** `official_convenio`/`national_law`. (b) `StoreReferenceFactRequest`/`UpdateReferenceFactRequest` accept `authority in:structured_reference` only and **reject (422) anything higher** (the Sprint-6 reject-not-clamp discipline, ADR-0019). **Test:** a POST/PATCH attempting `authority_level = official_convenio` → 422, nothing written; the column physically rejects it. This is "nothing the system generates outranks the law," by construction.
2. **Salary is structurally not swallowed into `reference_facts`, and reference content not into salary — routing rides `document_type`, never content (INVARIANT 2).** A `salary_tables`-tagged xlsx reaches `salary_table_rows` only via `salary:import`; a `reference_source`-tagged docx/xlsx reaches `reference_facts` only via the manual path. The reference writer **never** writes a `salary_table_rows` row (even if the source contains SMI figures — they land as a fact's `value`/`raw_values`). **Test (the Alhambra fixture):** a `reference_source`-tagged file produces only `reference_facts`, zero `salary_table_rows`; `salary:import` (which filters `document_type = salary_tables`) does not pick it up.

Plus the **inert-until-verified** reuse (the 7a/ADR-0020 spine): a fact lands `needs_review`, is **not** answerable until a human verifies (and since 7c isn't built, *no* fact is answerable yet — correct); provenance is **append-only** (`tag_events`, no rewrite).
