# Sprint 7d — Semantic conflict detection + version resolution + AI succession-proposal

> Location: `hr-docs/sprints/sprint-07d/spec.md`
> Reviewer: Claude (architecture) · eyes-on: Pedram
> Read first: **`architecture.md` §8.3** (the Sprint-4 publish conflict fence — topic-additive, fail-closed, the interim shape this sprint evolves), **§8.5** (the Q-F symmetric-recheck boundary), **§5 3b** (`hr-ai POST /retrieve` — the embed-and-rank primitive: BGE-M3, scope `WHERE`, forced-exact flat scan, full recall) and the read-only **`/sandbox-retrieve`** (ranks within one document); **7a** (`reviews:scan-expiry`, the human-confirmed `predecessor_document_id` write-side, same-convenio only, never auto-retire — ADR-0020) and the 7a note *"AI succession-proposal deferred to 7d"*; **7b-2** (`duplicate_of_id` + `uncertainty.field='version'` — signal only, *"resolution is 7d"*; the version-trap partial miss: file-2's re-grouped Navarra Intervención Social G2 was **not** linked to file-1's value because the exact-`group_label` key missed it — ADR-0022); **7c** (`ReferenceFactAnswerService`'s two-verified safe rule — most-recent validity else escalate — the answer-side stopgap 7d's resolution feeds); ADR-0011/0015/0016/0020/0021/0022; `roadmap.md` Sprint 7d.
> **One mechanism, three jobs.** All three deliverables are the same capability — *compare two pieces of knowledge by meaning and surface the relationship to a human* — pointed at three places: the publish fence, the fact duplicate queue, and the expiry queue. The comparison engine **already exists** (`/retrieve` embeds a query and ranks same-scope chunks by cosine); 7d **reuses** it, never rebuilds it. hr-ai gains at most one additive read-only comparison endpoint; it writes nothing and never migrates.
> **The non-negotiable posture (the roadmap's "safety tuning"):** where similarity drives a **safety gate** (the fence), fuzziness must **fail toward caution** — flag-for-human on plausible overlap, never silently decide "no conflict." Where it drives **growth/housekeeping** (succession, duplicates), it may **propose** freely, but a human confirms every retire/resolve/link. **Nothing in 7d auto-resolves, auto-retires, auto-publishes, or touches the frozen answer loop.**

## Goal
Upgrade the platform's three "is this the same thing / does this contradict that" decisions from crude structural proxies to **meaning-based comparison**, keeping every one of them human-adjudicated: **(A)** the ruling-publish conflict fence asks *"does the official convenio already address this specific point?"* instead of *"does any convenio share this topic tag?"* — and gets **stricter, never looser**; **(B)** 7b-2's flagged fact duplicates (and the re-grouped versions the exact key missed) get a **resolution surface** where a human picks supersede / coexist / reject with full provenance; **(C)** the expiry queue gains **AI succession-proposals** (successor / coexisting-sibling / conflict, by meaning) that a human confirms before `predecessor_document_id` is written.

## In scope

### A. The semantic publish fence (the safety gate — fail toward caution)
- At `internal_hr_ruling` publish (the Sprint-4 gate, `EscalationService::resolve` → the conflict check), **add** a semantic pass: embed the ruling's `resolution_text` (or reuse its freshly-embedded chunks — publish already runs `/embed`) and search the asker's scope for **semantically-close `official_convenio` chunks** (via `/retrieve` scoped to the convenio, or an additive read-only compare endpoint). If any active official-convenio chunk is close above a **conservative similarity threshold** → the ruling **may be addressing a point the convenio already governs** → **block (409 `publish_blocked`, reason `semantic_overlap`)**, return the card to In Progress, and show the human **the overlapping convenio passage(s)** so they can judge.
- **Stricter, never looser (the load-bearing rule).** The existing topic-additive / scope-only block **stays as-is** — semantic is **added on top**, so the fence can only block *more*, never less. `fence = existing_block OR semantic_block`. A sparse topic lens, a mis-tagged topic, or a similarity miss can never *open* a gate the old fence closed. (Cf. ADR-0019 raise-only; the Sprint-5 fail-closed correction.)
- **Thresholds are named config, conservative, raise-only-exposable** (`config/hr.php`, like the retrieval floor): `semantic_conflict_threshold` (block above), and — recommended — a lower `semantic_review_band` where the publish is **not** blocked but the human is **shown the near-passages and must acknowledge** ("no overlap — publish anyway") before proceeding. Two bands: certain-overlap blocks; plausible-overlap asks. Never silently "no conflict."
- **What is compared:** the ruling's substantive text vs the scope's **active `official_convenio`** chunks (and `national_law` as informational, never blocking on its own — the Estatuto is baseline, not a same-scope override target). The comparison is **read-only** over `document_chunks`; nothing is persisted except the `publish_blocked` / `publish_acknowledged_overlap` event with the matched chunk ids + scores (auditable: *why* it blocked).
- **§8.5 symmetric re-check — minimum bar only.** When an `official_convenio` is **newly ingested/verified** into a scope that has published rulings, run the same comparison in reverse and **flag** conflicting rulings into a review queue item (never auto-demote; never touch retrieval). This closes the Q-F boundary as a *flag*, not a resolution. (If it balloons, it's the first thing to defer — state so in the plan.)

### B. Fact version/duplicate resolution (housekeeping — human adjudicates)
- A **resolution surface** in the Reference-facts review tab for every fact carrying `duplicate_of_id` (7b-2's flag): show both facts side by side (scope, group_label, value, validity, source_excerpt, source doc, status) and offer **three actions**, each append-only-provenanced: **supersede** (the newer fact's validity closes the older — set the older's `validity_end = newer.validity_start − 1 day`, both remain, lineage recorded, the older stays `verified` for its window — this is the version-history discipline, never a delete), **coexist** (both genuinely apply — e.g. different sub-scopes — clear the flag, record the judgment), **reject** (the duplicate is wrong — the existing `rejected` status).
- **Catch the re-grouped versions the exact key missed** (the 7b-2 version-trap partial miss). Extend duplicate *detection* with a **semantic + scope** pass: for facts in the **same convenio + topic**, compare `group_label`/`value`/`source_excerpt` by meaning (embedding or a deterministic normalized-token overlap — the plan picks, deterministic preferred where it suffices) so *"Grupos 1 y 2 = 6 meses"* (file 1) and *"Grupo 2 = 4 meses"* (file 2) are surfaced as **possible version pairs** even though their labels differ. **Flag only** — the human resolves via the surface above. Never auto-link.
- **The 7c answer-side rule stays**: two verified same-validity conflicting facts still **escalate** in chat; 7d gives the human the tool to *fix the data* so it stops escalating. Resolution flows to the answer path through data, never through a new answer-path branch.

### C. AI succession-proposal on the expiry queue (growth — propose, human confirms)
- For each `reviews:scan-expiry` item (a near-expiry/expired active document), the AI **proposes** a relationship to candidate documents in the **same convenio** (7a's hard rule — succession is scope-based, never topic-based, never cross-convenio): **successor** (a newer version of the same scope — same convenio, later validity, high semantic overlap), **coexisting sibling** (same scope, different subject — low overlap, both should stay active), or **conflict** (same scope, same subject, contradictory content — needs adjudication). Each proposal carries the compared passages + a score + explicit uncertainty; it lands as an **`ai_agent`-provenanced proposal on the expiry task**, fuchsia, **inert** (ADR-0020).
- The human **confirms** → the existing 7a write-side runs (`predecessor_document_id` written, same-convenio, **the predecessor is never auto-retired** — retirement stays the document's own lifecycle decision). Reject → recorded, nothing written. The AI never writes `predecessor_document_id`, never flips `retrieval_status`, never retires.
- Reuses the 7a propose-pattern (queued job → hr-ai reads-and-returns → hr-backend persists the proposal → human confirms). Uses the **7b-2 eval discipline**: a small gold set of real expiry pairs (a true successor pair, a sibling pair, a conflict pair from the corpus) scored for *"proposed the right relationship / flagged uncertain / confidently wrong."* Confidently-wrong-successor is the failure to measure (it would tempt a human to retire a live document).

## Out of scope (do NOT build)
- **The answer loop** (2b/7c frozen) — 7d adds no retrieval/synthesis/grounding branch; the fence and queues are admin/publish-time surfaces. Resolution reaches chat only via corrected data.
- **Auto-anything:** no auto-resolve, auto-link, auto-retire, auto-demote, auto-publish. Every relationship is human-confirmed; every fence outcome is block-or-ask, never silent-pass.
- **Cross-convenio succession** (7a rule) and **topic-based succession** — never.
- **Loosening the existing fence** in any way; **lowering** any threshold (raise-only exposure only, per ADR-0019).
- **The question-granular flywheel growth** (matching future askers to precisely-placed resolved entries by meaning) beyond what the rulings' existing embed-and-retrieve already gives — the fence/resolution/succession machinery is the deliverable; a dedicated "knowledge-gap mining" surface is a Sprint-8 concern.
- **Vocabulary changes** (ADR-0011), **OCR** (7e), **group-scope modeling** (7f).

## Acceptance criteria
1. **(A)** Publishing a ruling that semantically overlaps an active official-convenio passage in scope is **blocked** (`semantic_overlap`) with the overlapping passage shown; a plausible-band overlap requires explicit human acknowledgement; **every case the old topic/scope fence blocked is still blocked** (a test proves `fence = old OR semantic` — the fence never fails open).
2. **(A)** Thresholds are named, conservative, raise-only; the block/acknowledge event records the matched chunk ids + scores (auditable why).
3. **(A, min bar)** A newly-ingested official convenio in a scope with published rulings **flags** overlapping rulings into review — never demotes, never touches retrieval.
4. **(B)** Every `duplicate_of_id` fact has a side-by-side resolution surface with supersede / coexist / reject, each append-only-provenanced; **supersede closes validity, never deletes**; the semantic/scope pass surfaces the re-grouped version pair the exact key missed as a **flag** (the 7b-2 Navarra Intervención Social case is the gold test).
5. **(C)** Expiry items carry an `ai_agent` succession proposal (successor / sibling / conflict + compared passages + uncertainty), **inert** until a human confirms; confirm runs the 7a write-side (same-convenio only, predecessor never auto-retired); the AI **never** writes lineage or status. A small real-pair gold eval reports right / uncertain / confidently-wrong, and confidently-wrong-successor is 0 (or flagged) on the fixtures.
6. **hr-ai reads/returns only** (one additive compare endpoint at most, or `/retrieve` reused); never migrates; hr-backend owns every write; additive migrations only; **the answer loop is byte-for-byte unchanged** (the 7c golden-trace regression still passes).

Ask a chat question → answers exactly as before (nothing in the loop changed).

## Risks / notes
- **The fence is a safety gate — it must only get stricter.** The single most important test: *every publish the old fence blocked, the new fence still blocks.* Semantic is additive. If implementation tempts you to "replace" the topic check because semantic is smarter — don't; a similarity miss must never open a door the crude check closed.
- **Similarity is fuzzy; safety isn't.** Two bands (block / acknowledge), conservative thresholds, and the matched passages *shown* to the human are what make fuzziness safe. Never a silent "no conflict."
- **Succession's failure mode is a confidently-wrong successor** — it tempts a human to retire a live document (silently deleting information for a population, the 7a warning). Hence: proposals are inert, same-convenio only, the predecessor is never auto-retired, and the eval measures confidently-wrong explicitly.
- **Supersede ≠ delete.** Version history is the point: closing the older fact's validity keeps the historical answer correct for its window (a 2025 question still gets the 2025 value). Never delete a verified fact.
- **Scope creep guard.** Three jobs on one mechanism is already an M; the §8.5 reverse re-check is the first thing to defer if it balloons. Keep hr-ai to one additive read-only endpoint at most.
