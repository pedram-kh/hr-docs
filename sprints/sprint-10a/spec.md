# Sprint 10a — Spec: Clarifying-question turn + Estatuto fallback for full-gap convenios

> Save as: `hr-docs/sprints/sprint-10a/spec.md`
> Status: SPEC — plan gate next. No code until plan is reviewed and build is authorized.
> Depends on: ADR-0015/0016 (AI never decides), ADR-0023 (7c additivity), ADR-0028 (group scope), ADR-0030 (coverage service). New ADRs this sprint: **ADR-0031** (clarifying turn), **ADR-0032** (Estatuto fallback).

---

## 1. Goal

Raise deflection and accuracy **without loosening any safety rule**, via two additive changes to the answer loop:

1. **Clarifying-question turn.** Today the loop is binary (answer | escalate). Many escalations are caused by one missing *question parameter* (seniority, absence type, year). Add a third outcome — ask the employee **one** deterministic clarifying question, then re-run the loop once.
2. **Estatuto fallback.** Employees whose resolved convenio has **zero ingested text** (the 9 full-gap convenios) currently escalate on almost everything. When the convenio corpus is empty, allow answers from `national_law` alone, with a mandatory fixed caveat that the convenio may improve on the legal minimum.

Both changes are strictly additive: every question answerable today must produce a byte-for-byte identical trace (golden-trace regression stays green).

## 2. In scope

### 2.1 Clarifying-question turn (`clarify`)

- New loop outcome `clarify`, decided by **deterministic hr-backend code only**. No LLM ever writes or selects the question.
- A **closed clarification matrix** (pattern of the 7g `explanation_facts` matrix): `escalation_reason × missing_parameter → fixed question text (es)`. Guard-tested so every clarifiable entry has exactly one question.
- **Clarifiable parameters are question parameters only** — facts about the *question*, never directory-owned scope. Allowlist (initial, closed): `seniority_years`, `absence_type` (from a closed enum shown as options), `reference_year`, `contract_time` (full/part-time). **Territory, sector, convenio, and group are NEVER clarifiable** — they come from the directory (ADR-0028) or the question escalates as today.
- **Hard limits:** max **one** clarification per user question. After the clarified re-run, the outcome is answer or escalate — never a second question. Re-run uses the same frozen loop; the clarified parameter is injected as typed context, not free text.
- **Echo rule:** any answer produced after a clarification must open with a deterministic assumption line, e.g. *"Según lo que indicas (5 años de antigüedad): …"*, appended by hr-backend (not synthesized).
- **Persistence:** clarified values live in the message trace (`floor_decision.clarification = {parameter, value, matrix_key}`) and the conversation only. They are **never written to the employee directory**.
- Frontend: render the clarify turn in employee chat (question + option chips for enum parameters; numeric input for years). Trace visible in the admin conversation view.

### 2.2 Estatuto fallback (`estatuto_gap`)

- **Trigger condition (deterministic, checked in hr-backend before routing):** the employee's resolved convenio has **zero prose chunks** in `document_chunks`. Source of truth: the same query `CorpusCoverageService` uses for full-gap classification — do not duplicate logic; extract/reuse.
- Partial-gap convenios do **not** qualify. If any convenio text exists, behavior is unchanged (the convenio might govern the exact topic asked; answering from Estatuto would violate authority precedence).
- When triggered: prose path runs with retrieval restricted to `national_law` scope; synthesis, figure-guard, and `/ground` all apply unchanged; answer authority recorded as `national_law`; trace records `floor_decision.fallback = "estatuto_gap"`.
- **Mandatory caveat:** a fixed string appended deterministically by hr-backend to every fallback answer: *"Tu convenio colectivo puede mejorar estas condiciones. Esta respuesta se basa únicamente en la legislación laboral general (Estatuto de los Trabajadores), que establece los mínimos legales."* Never generated by the LLM. Guard-tested: no fallback answer can persist without it.
- **Exclusions:** the salary path never falls back (the Estatuto states no salary figures; SMI questions escalate as today). Reference-fact pre-check unchanged. Guardrail baseline runs first, unchanged.
- Escalations from a fallback attempt carry a distinct reason so Analítica can separate "gap convenio, Estatuto couldn't answer either" from ordinary coverage gaps.

### 2.3 Evals (the deliverable, per standing rule)

- **Clarify eval:** gold set built from **real escalation cards on staging** (start from the top cluster — periodo de prueba — plus vacaciones/permisos cards). Measure: (a) share of gold escalations converted to a correct answer after one clarification, (b) **zero** answers whose correctness depends on an unclarified or mis-echoed assumption, (c) zero directory writes.
- **Fallback eval:** gold set of questions from full-gap-convenio test employees, answerable from the Estatuto (vacation minimum, art. 37 permisos, probation maxima, preaviso). Measure: (a) answer rate vs today's ~0, (b) all answers grounded, (c) caveat present on 100%, (d) zero convenio-specific claims, (e) salary questions still escalate.
- **Additivity:** `Sprint7cAdditivityRegressionTest` green; extend the golden set with 2–3 traces exercising today's escalation behavior for a *partial*-gap convenio (must be unchanged).

## 5. Risks / decisions to surface at plan gate

- **R1 — self-asserted parameters.** An employee can lie or err about seniority. Mitigation is the echo rule + trace, and restricting the allowlist to parameters where the answer is naturally conditional ("con X años…"). The plan must confirm the allowlist against real escalation cards: if a card's missing parameter is actually directory scope (e.g., unassigned group), it is **not clarifiable** — the fix link stays "assign the group."
- **R2 — retrieval scope for fallback.** Confirm `/retrieve` can be cleanly restricted to `national_law` without touching the recall-hardened union logic for normal paths.
- **R3 — Estatuto chunk quality.** The handoff notes the Estatuto was deliberately held out of the 2c re-chunk. The plan must check whether current Estatuto chunks are good enough for a national-law-only answer path, or whether re-chunking it (article-boundary) becomes a prerequisite step of this sprint.
- **R4 — chat UI state.** The clarify turn is the first non-terminal assistant turn in employee chat; confirm message/trace model supports a pending-clarification state cleanly (and what happens if the employee ignores the question and asks something new → treat as a new question, expire the pending clarification).
- **R5 — coverage-service reuse.** Full-gap classification must come from one shared source; a second definition drifting from `CorpusCoverageService` is the exact "two definitions of truth" failure class.

## 8. Plan-gate addendum (written after the plan gate, D8)

This section records where the spec above was overtaken by what the plan found in the real code and the real corpus. The spec is left intact above rather than rewritten, so the delta is visible.

**Re-scoped to the fallback only.** Sprint 10a shipped §2.2 (the Estatuto fallback) and deferred §2.1 (the clarifying-question turn). The reason is in `plan.md` §A: zero of the eleven real escalation cards on staging would be converted by a clarifying question, no entry in the `explanation_facts` matrix has a missing question parameter as its cause, and two of the four allowlisted parameters (`contract_time`, `seniority_years`) turn out to be directory columns — which the spec's own R1 rule excludes. A falsification probe was run in place of the build and is recorded in `review.md` §9; it found zero cases across the real answered turns. **ADR-0031 stays reserved and unwritten.**

**R4 is factually wrong.** The clarify turn would not have been "the first non-terminal assistant turn in employee chat". `needs_category` has been exactly that since Sprint 2b — constrained options, no escalation card, no directory write, re-run with a typed parameter, with working frontend UI. That is good news for whenever the clarify turn returns: the model and the UI pattern already exist, and it should be built *as* that pattern rather than as a new state machine.

**The `explanation_facts` matrix is not 39 keys.** It was 44 after Sprint 8 and is **48** after this sprint's four `estatuto_fallback_gap` sub-outcomes. The count in the living docs has been corrected and dated; sprint-dated documents keep their original figures, which were true when written. `EscalationExplainerGuardTest` enforces completeness, so the number is descriptive rather than load-bearing.

**Eyes-on §6 is revised.** Items 1, 2 and the `clarification` half of item 6 are **not applicable** — they test the deferred half. Items 3, 4, 5 and the `fallback` half of item 6 stand as written, with one correction: item 3's employee is `test-fullgap@example.com` on **convenio 7**, not the convenio 16 named in the build authorization's D5. Convenio 16 has a historical convenio text, which D3's tightened predicate classifies as `expired_only` — so it moved to the other side of the split and became a second negative control (`test-midingest@example.com`). Convenio 7 is the only non-fixture convenio in the corpus that satisfies `never_ingested`.

**A new eyes-on item §6.7 — the expired-convenio negative.** Log in as `test-andalucia@example.com` (convenio 4, an expired text *with* chunks) and ask the same holiday question item 3 asks. It must escalate, the employee must see the ordinary neutral message with no hint of the cause, and the admin trace must show `prose_gap.classification = "expired_only"` with **no** `floor_decision.fallback` key. Then repeat as `test-midingest@example.com` (convenio 16, an expired text with *zero* chunks), which must behave identically while reaching that verdict by the other route. This is the item that demonstrates the sprint's central decision, and it is the one to run first if there is only time for one.

**ADR path.** The ADR is at `hr-docs/architecture/decisions/0032-estatuto-fallback.md`, matching the existing numbering convention on disk, not the `hr-docs/adr/ADR-0032-…` path §7 names.
