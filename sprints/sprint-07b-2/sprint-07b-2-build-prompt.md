## The blocker — resolved (build this first)

**Q1 — the logical-key / null-`job_category` collision: add a nullable `group_label` column and fold it into the upsert key.** Because `convenio_job_categories` is salary-derived and unseeded for the periodo convenios, `job_category_id` is usually null, so "Grupo 1/2/3" facts for the same convenio+topic+validity would all collide on `(convenio_id, topic_id, job_category_id, validity_start, validity_end)` and the upsert would clobber them. Fix:
- Add **`group_label varchar NULL`** to `reference_facts` (the group as written — "Grupo 1", "Grupo 2 (resto áreas)", "Obreros y subalternos"), normalized for matching (trim/collapse/case-fold) but stored as-seen.
- The **upsert match becomes `(convenio_id, topic_id, job_category_id, group_label, validity_start, validity_end)`** — the group is a first-class identity discriminator, not buried in `raw_values`. When a real `job_category_id` exists it's used too; `group_label` carries the (common) cases where it doesn't.
- Update `ReferenceFact::LOGICAL_KEY` accordingly. This **must** be in place before the persist path so the agent can store all of a file's per-group facts without self-clobbering. **Test:** ingesting file 1 produces *distinct* facts for Álava COEAS G1/G2/G3 (not one clobbered row).

- **Q4 — obvious-duplicate = logical-key collision with a *differing* `value`**, flagged via `duplicate_of_id` + `uncertainty.field='version'`. **Signal only — no winner picked** (resolution is 7d). No value-comparison beyond exact-key-plus-different-value.
- **Q5 — add a `rejected` status** (small enum alter on `reference_facts.status`) so a rejected proposal is auditable and excluded from the queue without deletion (over a soft-delete timestamp).
- **Q6 — bind `topic_id` to the approved "periodo de prueba" topic; SEED that topic (additive, deliberate) so the eval can score.** The agent never mints topics (ADR-0011); the seed is an admin action. If the topic is somehow absent at runtime, leave `topic_id` null + flag — never mint.
- **Q7 — hr-backend derives `validity_start/end` from the source `documents` row (human-set at ingest); the agent does NOT parse dates from prose.** Date-parsing from text is deferred (error-prone).
- **Q8 — the Alhambra xlsx routing test: expect ZERO salary rows and zero-or-a-small-handful of facts; any salary-shaped fact is an EVAL FAILURE.** Zero facts is an acceptable/preferred result — the test proves salary isn't swallowed, not that facts are extracted from a salary grid.
- **Q9 — feed the FULL concatenated pages text** (78/95 paragraphs is small) so the header-carry reset logic sees the whole sequence. A per-section call would break header-carry (§1.4) — do not chunk.
- **Q10 — the agent re-derives the TERRITORY→SECTOR→group hierarchy from the text, NOT the reader's sections** (unreliable across the two files — §1.4). Pass `pages` only for `locator`/`source_excerpt` anchors. No reader change this sprint unless the eval shows locators are insufficient.
