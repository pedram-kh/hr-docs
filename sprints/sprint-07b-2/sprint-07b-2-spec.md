# Sprint 7b-2 — The AI segmentation agent (Structured Reference Knowledge, the AI half)

> Location: `hr-docs/sprints/sprint-07b-2/spec.md`
> Reviewer: Claude (architecture) · eyes-on: Pedram
> Read first: **ADR-0020** + the 7a build (the `/propose-tags` → queued-job → `ai_agent`-provenance → inert-until-verified pattern — **the exact template**); **ADR-0021** + the 7b-1 build (the `reference_facts` table with the **reserved `ai_agent` lane**, the `needs_review` state, the **logical key** `(convenio_id, topic_id, job_category_id, validity_start, validity_end)` recorded *for this sprint's upsert*, the `/read-structured` docx/xlsx reader, the distinct-badged leaf + fact card + verify UI); `roadmap.md` Sprint 7b (the full vision — esp. *the central design risk is scope-assignment*, *authority err-low-never-high*, *the hard boundaries*); ADR-0007 (hr-ai reads/returns, never migrates), ADR-0011 (bind into existing vocabulary only); the canonical fixtures (now in-repo — see §Eval).
> **The single riskiest sprint in the project.** Not because the plumbing is hard (it reuses 7a's proven propose-pattern and writes into 7b-1's proven `reference_facts`), but because the **one cognitive task — segment a multi-scope file into facts and assign each the right scope — is where a wrong guess becomes a confident, exact, wrong answer** (the worst failure mode). The safety net (inert-until-verified, fuchsia, human-confirms) is **already built and proven**; a wrong AI fact is harmless *until a human verifies it*. So the real risk is **plausible-looking wrong proposals that a human rubber-stamps** — which makes the **eval** and the **review UX** the substance of this sprint, not the wiring.

## Goal
Build the AI agent that reads a `reference_source` docx/xlsx and **proposes** the individual scoped facts — segment → assign each its scope/topic/validity → propose as `ai_agent`/`needs_review` into `reference_facts` (the lane 7b-1 reserved) — reusing 7a's inert-until-verified spine. The agent does the **high-volume tedious work** (read/split/draft-scope); the human does the **low-volume judgement** (verify/fix). **The deliverable is not "it runs" — it is a measured accuracy report on the real fixtures showing the scope-assignment is good enough that human review catches errors rather than drowning in them.**

## The inherited safety net (already built — preserve, don't rebuild)
- **Inert until verified (ADR-0020/0021):** an AI-proposed fact lands `source = ai_agent`, `status = needs_review`, **not answerable** (and not answerable at all until 7c). Only a human verify flips it. The agent **never** verifies its own output.
- **Authority structurally bounded (ADR-0021 INVARIANT 1):** the agent can only ever propose `structured_reference` — the column can't hold higher; the request rejects 422. Re-proven, not rebuilt.
- **Routing by `document_type` (ADR-0021 INVARIANT 2):** the agent runs only on `reference_source` docs; salary stays on `salary:import`. Never writes a salary row.
- **Fuchsia `--provenance-ai`:** AI-proposed facts are fuchsia (unverified-AI) until verified — the lane 7a defined, now lit for facts.
- **hr-ai reads/returns, hr-backend persists (ADR-0007):** the agent's LLM call returns proposed facts; **hr-backend writes** them; hr-ai never migrates.
- **Bind into existing vocabulary only (ADR-0011):** the agent assigns into existing convenios/territories/sectors/topics/categories; where it can't resolve a value, it records uncertainty — it **never** mints vocabulary.

## In scope

### A. The segmentation agent (the new cognitive work)
- A queued job (the 7a `ProposeDocumentTags` posture) dispatched for a `reference_source` document: call `/read-structured` (7b-1) → pass the structured content + the **closed candidate vocabulary** (convenios/territories/sectors/topics/categories, the 7a candidate-list discipline) to an hr-ai segmentation endpoint (`POST /segment-facts`) → receive an array of proposed facts → **hr-backend persists** each as an `ai_agent`/`needs_review` `reference_fact`, **upserting on the logical key** 7b-1 recorded.
- Each proposed fact carries: the **scope** (convenio→derived territory/sector, optional job_category/topic), the **value** + `raw_values` verbatim, **validity** (from the source's own version — see §C), **authority** (`structured_reference`, fixed), a **confidence signal**, the **exact source locator** (the line/section it came from), and an **explicit uncertainty flag** where the agent couldn't confidently resolve scope.
- **Multi-value lines → one fact per scope** (decision): a line like *"Grupo 1: 90 días (indefinidos) / 75 (temporales >3m) / 60 (≤3m)"* becomes **one** fact for that scope, the full contract-type breakdown preserved in `value`/`raw_values` — not three facts. The *scope* is the answerable unit; the breakdown lives inside it.
- **hr-ai never writes** (ADR-0007); it returns the proposed-facts envelope. The agent does **not** make anything answerable, create vocabulary, touch the answer engine, or handle salary (the 7b boundaries).

### B. The review experience (the safety is the UX)
- Because the agent **will** mis-scope on hard material, the reviewer must verify **fast and accurately**. Each proposed fact in the review queue shows, inline: **the exact source line/section it was extracted from**, the **scope it assigned** (territory/sector/group), its **confidence**, and its **uncertainty flag** if set — so the human checks "did the source really say Álava?" against the quoted line, not by re-reading the file.
- The reviewer can **verify** (accept), **fix-then-verify** (correct the scope/value via the 7b-1 bounded edit, then confirm), or **reject** (discard the proposal). Fuchsia until verified; reverts to normal on verify with the AI origin in the provenance timeline.
- **Uncertainty surfaces first:** facts the agent flagged as low-confidence/uncertain sort to the top of the queue (the ones most needing human judgement).

### C. Version/validity (propose-with-source-validity; conflict resolution is 7d)
- Each fact is tagged with **its source file's validity** (e.g. the 2026 file → 2026 validity). The agent does **not** decide which version "wins."
- Where the agent detects an **obvious same-scope duplicate** (the logical key collides with an existing fact of a different value — e.g. Navarra Intervención Social 6 vs 4 meses across the two periodo files), it **flags it for the human** as a possible version/update — a *signal*, not a resolution. **The real semantic-conflict resolution is Sprint 7d** (we don't build conflict detection twice); 7b-2 only surfaces the obvious-duplicate signal so the human isn't blindsided.

## The eval — the spine of this sprint (the actual deliverable)
Run the agent on the **real in-repo fixtures** and report a **measured accuracy table**, not a pass/fail. The fixtures and the specific traps each exercises (read from the actual files):

- **`PERIODOS_DE_PRUEBA.docx`** (78 paragraphs, prose, no tables) — the **territory-carry** trap (a `TERRITORY`→`SECTOR` header governs the `Grupo X: value` lines beneath it until the next header; the agent must carry context down and **reset on each new header** — `ESTATAL`→`ALAVA`→`ANDALUCÍA`→`GUIPUZCOA`→`VALENCIA`→`VIZCAYA`→`NAVARRA`); the **cross-province disambiguation** trap (COEAS **Álava** Grupo 1 = *Cinco meses* vs COEAS **Andalucía/Estatal** Grupo 1 = *Seis meses* — same sector+group, different value by province — a single mis-attribution is a wrong exact answer); the **multi-value** trap (Navarra Hostelería Grupo 1 → 90/75/60 by contract type); compound group expressions (*"Grupo 1 y área cinco de Grupo 2"*) that don't map to one category.
- **`PERI_ODOS_PRUEBA_ACTUALIZADOS_2026.docx`** (95 paragraphs) — the **version** trap: same domain, **genuinely changed values** (Navarra Intervención Social Grupo 2 = *Seis Meses* in file 1 → *4 meses* in file 2), **province-spelling variance** (GUIPUZCOA vs GIPUZKOA), and territories present in one file but not the other (Madrid, Bizkaia). Tests validity tagging + the obvious-duplicate flag (not resolution — that's 7d).
- **`Tablas_acuerdo_parcial_Alhambra.xlsx`** (sheet `Convenios`, 714×28, salary-ish: `SMI 2025: 16576`, `hs/año: 1742`) — the **routing test**: tagged `reference_source` → reference facts only; **zero salary rows** (Invariant 2); the agent must not turn SMI figures into salary.

**The accuracy report (the deliverable):** for the two docx, a table of *facts proposed* vs *facts correct (scope+value+validity)* vs *mis-scoped* vs *correctly-flagged-uncertain*, with the **mis-scoped ones enumerated** (which line, what it assigned, what was right). This is reviewed as the sprint's real output — "the agent proposed N facts, M fully correct, the K errors were these and the human-review UI surfaces each with its source line." A high mis-scope rate that the **review UX makes catchable** is acceptable for a human-gated tool; a mis-scope rate that would **drown** the reviewer is the failure signal.

## Out of scope (do NOT build)
- **Answering from facts (7c)** — still untouched; a verified AI fact is no more answerable than a verified manual one until 7c. The answer engine is **not** touched (2b frozen).
- **Semantic conflict *resolution* / version-wins logic (7d)** — 7b-2 proposes with source-validity + flags obvious duplicates; it does not resolve which wins.
- **Vocabulary creation** (ADR-0011 — bind only; uncertainty where unresolvable), **salary** (salary path), **the carried document-confirm-route gating** (still a logged follow-up, not this sprint).
- **OCR** (7e — a `reference_source` scan with no text layer is skipped with `no_extractable_text`, the 7a posture).

## Acceptance criteria
1. A `reference_source` doc auto-triggers (queued) the segmentation agent → hr-ai `/segment-facts` returns proposed facts → hr-backend persists them as `ai_agent`/`needs_review` `reference_facts`, **upserting on the logical key**, each with scope/value/validity/confidence/**source-locator**/uncertainty. hr-ai writes nothing, never migrates.
2. The inherited invariants hold (re-proven, not rebuilt): AI facts are `needs_review` + **not answerable**; authority can only be `structured_reference` (422 on higher); **zero salary rows** from the reference path; the agent mints **no** vocabulary.
3. **Multi-value lines → one fact per scope** (breakdown in value/raw_values). **Version:** each fact tagged with its source validity; an obvious same-scope duplicate is **flagged** (not resolved).
4. **The review UX** shows each proposed fact with its **source line**, assigned scope, confidence, and uncertainty flag; the human can verify / fix-then-verify / reject; uncertain facts sort first; fuchsia until verified.
5. **The eval report exists and is the deliverable:** the agent run on the three fixtures, with the accuracy table (proposed / correct / mis-scoped / flagged-uncertain) and the mis-scoped facts enumerated. The review concludes whether the error rate is *human-catchable* (acceptable) or *drowning* (needs prompt/segmentation iteration).

## Risks / notes
- **The eval is the sprint.** Treat the accuracy report as the primary deliverable; the code is the means. If the first run mis-scopes badly, iterate the segmentation prompt / the candidate-vocabulary context / the header-carry instruction *before* declaring done — this is the one sprint where "iterate against the eval" is expected, not a failure.
- **The review UX is the safety.** A reviewer who can't see the source line will rubber-stamp. The inline source-line + confidence + uncertainty-first sort are not nice-to-haves; they are the structural defense against plausible-wrong proposals.
- **The header-carry instruction is the highest-leverage prompt detail.** The docx structure is "header governs following lines until next header"; the agent must be told this explicitly and reset scope on each `TERRITORY`/`SECTOR` header. Most cascading errors will come from getting this wrong.
- **Err low on authority, flag on uncertainty** (the roadmap rule): the agent proposes `structured_reference` always; where scope is unclear it **flags uncertain** rather than guessing — a flagged-uncertain fact is a success (the human decides), a confidently-mis-scoped fact is the failure.
- **Don't rebuild 7d.** The obvious-duplicate flag is a lightweight signal (logical-key collision with a different value); the real semantic comparison is 7d. Keep the boundary.
- **hr-ai stays a stateless reader** (ADR-0007) — `/segment-facts` returns proposals; all writes are hr-backend's.
